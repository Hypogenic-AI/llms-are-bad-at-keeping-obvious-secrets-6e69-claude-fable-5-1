# Notes: Do Language Models Plan Ahead for Future Tokens? (arXiv 2404.00859v2)

Wilson Wu (CU Boulder), John X. Morris (Cornell), Lionel Levine (Cornell). COLM 2024. Read in full: 24 pages, main text + Appendices A (myopia bonus/malus), B (myopic attention), C (proofs), D (experimental details, multiplication, gradient angles).

Numbers marked "(~, read off plot)" are my approximate readings of figures; all other numbers are printed in the paper.

## 1. Research question

It is known that hidden states at position t carry information used at later positions t+tau. *Why?* Two competing explanations:
- **Pre-caching**: "The model 'deliberately' computes and stores features that are expected to be useful for the future, even if they are irrelevant to the present." Caused by off-diagonal gradient terms (loss at position j > i flowing back to the computation at position i).
- **Breadcrumbs**: "The features that most benefit the present inference task are the same as those that are most useful to the future. When the model performs the present forward pass, it 'unintentionally' leaves a trace ('breadcrumbs') that is then picked up by future passes."

The question is to what extent a transformer spends current-position compute on the future at the expense of the current token.

## 2. Methodology

### Theory (Sec 3, App A, C)
- Treat the transformer as if each position i had its own parameters theta_i. Total loss gradient with tied weights is a sum over an upper-triangular matrix of terms grad_{theta_i} l_j (i <= j). Off-diagonal terms (i < j) are the training signal for pre-caching.
- **Myopic model**: each forward pass optimises only its own position's loss given a fixed past. Tied-weights definition (Def 3): theta~ in argmin_theta sum_i l_i(theta~, ..., theta~, theta).
- **Myopia gap** (Def 2/3): loss of the best myopic model minus loss of the best unconstrained model (>= 0). Breadcrumbs hypothesis = the gap is small. The gap is a property of architecture + data distribution.
- **Local myopia bonus** (Def 4) for a specific trained model theta*: how much the current-position loss could improve if the current pass were re-optimised while the past hidden states stay those of theta*. Measures how much that particular model is sacrificing present accuracy for the future.
- App A: myopia gap = myopia bonus (<= 0, gain from ignoring the future) + myopia malus (>= 0, cost to the future from not pre-caching). A small gap does not by itself imply both parts are small, hence the local bonus measurement.
- **Myopic descent**: gradient descent with the off-diagonal terms removed. Theorem 13: if f(theta~, theta) = sum_i l_i(theta~,...,theta~,theta) is forward-biased (Def 11), sigma-strongly convex and L-smooth, myopic descent with tied weights converges to a myopic solution.

### Implementation: myopic attention mechanism (App B)
One attention module that uses different key/value states for past positions than for the current position, while still computing all positions in parallel:
- Y~ = A V~ + (diag A)(V - V~), with A := softmax(Q K~^T + diag(Q (K^T - K~^T))), where K~, V~ are the alternate (past) key/value states.
- **Myopic descent**: past key/value states = W_K, W_V applied to a *cloned and detached* copy of the previous hidden states (stop-gradient into past positions). W_K and W_V are considered to belong to the attending (current) pass, so they still receive gradient.
- **Local myopic model**: past key/value states come from a separate frozen pre-trained (vanilla) model, in both training and inference.
- **Transformer bigram**: past key/value states zeroed out, in both training and inference.

### Experiment 1: synthetic task D_p (Sec 4.1, App D.1)
- Data: x_n ~ N(0,1); z_n ~ Bernoulli(p); y_n = z_n * sum_{i=1..a} sin(b x_{n-i}) + (1 - z_n) x_n. a = b = 10, sequence length N = 64. Pre-computing sin(b x_n) at position n is useless for y_n but useful for later positions.
- Model: small GPT-2-style regression transformer: 2 layers, 2 heads, embd_dim 128, n_inner 512, input_dim 2, output_dim 1, ReLU, no dropout, lr 1e-3, AdamW, weight decay 0.01, betas (0.9, 0.999), cosine schedule, warmup 0.01, batch 512, seq length 64, Huber loss. Token embedding/unembedding replaced by trained linear maps.
- Training: p in {0.01, 0.1, 0.3, 1}; one epoch of 30M sequences; vanilla vs myopic descent.
- **Probe**: linear regression from the hidden state of each layer (layer 0 = input + position embedding, layers 1 and 2) to targets sin(b x_{n-i}) for varying i; report in-sample R^2 over 50,000 evaluation sequences. Also per-neuron Pearson correlations between each hidden dimension and x_{n-i} or sin(b x_{n-i}).
- Probe validity safeguard: target is not linearly computable from the input, since rho(x, sin(bx)) < 10^-20 for b = 10 (Lemma 15), i.e. "the function to be learned cannot possibly be computed by the probe itself".

### Experiment 2: multiplication (Sec 4.2, App D.3)
- GPT-2 small architecture from random init. Input format e.g. `3 7 0 0 * 5 4 0 0 = 5 8 2 3 0 0 0 0` (digits space-separated, reversed order so least significant digit first, zero-padded to equal length).
- One epoch of 10M examples with up to 8 digits; 0/1 exact-match accuracy on 1024 validation examples for each of the 8x8 digit-count pairs.
- Filler-token variant: multiplicands with at most 5 digits zero-padded to exactly 5 vs exactly 10 digits (again 10M examples, one epoch).

### Experiment 3: natural language, GPT-2 (Sec 5.1, App D.2.1)
- GPT-2 small architecture (124M; 12 layers, 12 heads, 768 dim, n_inner 3072, vocab 50257, gelu_new, dropout 0.1, lr 6.0e-4, AdamW, wd 0.01, cosine, warmup 0.01, batch 512, seq length 64, cross-entropy).
- All models trained **from random initialisation** for one epoch on 4.6M sequences from MS MARCO truncated to 64 tokens.
- Four models: vanilla, myopic, local myopic (past states from frozen vanilla model), transformer bigram.
- Per-position loss evaluated on a sliding window over a 100K-token sample from PG-19.

### Experiment 4: scaling with Pythia (Sec 5.2, App D.2.2)
- Pythia 14M, 31M, 70M, 160M, 410M, 1B, 1.4B, 2.8B, **fine-tuned from the released pre-trained checkpoints** with vanilla or myopic descent on one epoch of 10M sequences of 64 tokens subsampled from The Pile (same subsample for every run).
- Learning rate / batch size: 14M 4.0e-4/512; 31M 4.0e-4/512; 70M 1.2e-4/512; 160M 1.2e-4/512; 410M 1.2e-4/256; 1B 1.2e-4/128; 1.4B 1.2e-4/128; 2.8B 8.0e-5/64. Other hyperparameters as in Biderman et al. (2023).
- Evaluated on validation cross-entropy and on LAMBADA, PIQA, SciQ, ARC-Easy accuracy.

### Experiment 5: gradient angles (App D.4)
Using public Pythia-410M training checkpoints: norms of the myopic component and the future component (total minus myopic) of the gradient over training, and their cosine similarity.

## 3. Datasets and sizes
- Synthetic D_p: 30M training sequences of length 64 per p; 50,000 evaluation sequences for probes.
- Multiplication: 10M training examples; 1024 validation examples per digit-count pair.
- MS MARCO: 4.6M sequences truncated to 64 tokens (GPT-2 training).
- PG-19: 100K-token sample (per-position evaluation).
- The Pile: 10M sequences of 64 tokens (Pythia fine-tuning).
- LAMBADA, PIQA, SciQ, ARC-Easy: benchmark sizes not stated.

## 4. Baselines
- Vanilla training (reference for every comparison).
- Transformer bigram (no access to past positions) as the lower bound on using the past at all.
- Trivial always-zero predictor on D_p (Huber loss 1.26).
- Local myopic model as an estimate of the local myopia bonus.

## 5. Metrics
Myopia gap (loss or accuracy difference vanilla vs myopic); local myopia bonus; validation cross-entropy; normalised Huber loss L/p; linear-probe R^2; per-neuron correlation; exact-match multiplication accuracy; benchmark accuracy; gradient norms and cosine similarity.

## 6. Key quantitative results

### Synthetic D_p: clear pre-caching
Table 1, normalised Huber loss L/p (trivial zero model = 1.26):
| p | Vanilla | Myopic |
|---|---|---|
| 0.01 | 0.096 | 1.10 |
| 0.1 | 0.016 | 0.97 |
| 0.3 | 0.0030 | 1.03 |
| 1.0 | 0.0074 | 1.26 |

Probe results (Fig 2, vanilla): layer 0 at position n correlates only with x_n; layer 1 linearly encodes sin(b x_n) (the pre-cached quantity, useless for the current output) but no sin(b x_{n-i}) for i > 0; layer 2 correlates with sin(b x_{n-i}) for 0 <= i <= a. Layer-1 R^2 for sin(b x_n) is roughly 0.85-0.95 for p in {0.1, 0.3, 1} and roughly 0.45 for p = 0.01 (~, read off plot); layer-2 R^2 for each lagged term i = 1..10 is roughly 0.1 (~, read off plot). Per-neuron correlations: the lagged terms share one 1-d subspace of layer 2 (the sum), while sin(b x_n) and the x_{n-i} sit in other 1-d subspaces "left over in the residual stream from previous layers, and are cleaned up only by the output unembedding". Pre-caching is learned even at p = 0.01, where the cached value is often never used. The myopic model appears to implement a crude brute-force algorithm and is close to the trivial baseline.

### Multiplication (Fig 9, 10)
- Vanilla and myopic both reach 1.00 on small digit counts. Vanilla minus myopic accuracy gap is large on mid-difficulty cells, e.g. 0.30, 0.50, 0.65, 0.73 for 4-digit x (5, 6, 7, 8)-digit and 0.53, 0.77 for 5x5 and 5x6.
- Filler tokens: for the hardest 5x5 cell, vanilla accuracy is 0.40 with padding to 5 and 0.99 with padding to 10; myopic is 0.39 with padding to 5 and 0.05 with padding to 10. Vanilla uses the extra filler positions for computation (pre-caching); the myopic model cannot and gets worse.

### GPT-2 on natural language: mostly breadcrumbs
Table 2, validation cross-entropy:
| Model | Cross-entropy |
|---|---|
| Vanilla | 3.28 |
| Myopic | 3.40 |
| Local myopic | 3.26 |
| Transformer bigram | 5.33 |

- Myopia gap = 3.40 - 3.28 = **0.12**. Local myopia bonus = 3.28 - 3.26 = **0.02**.
- Gap is small relative to vanilla vs bigram (5.33 - 3.28 = 2.05), so the myopic model "is still able to leverage past information (breadcrumbs) to a significant extent".
- By position (Fig 4, PG-19; aggregate CE 4.67 vanilla, 4.77 myopic): the myopic model is *better* at the very start of the sequence (gap about -0.10 at position 0) "since it can allocate all compute to next-token prediction", then falls behind; gap grows with position to about +0.11 to +0.12 by position 60 (~, read off plot).
- Near-zero local bonus: "the model learned through vanilla training does not trade off significantly between features useful for the present and pre-caching for the future."

### Scaling (Pythia, Fig 5, Fig 7)
- Validation CE gap between vanilla and myopic fine-tuning: "Starting from the 70M model, we see that the gap increases with parameter count." Largest model (2.8B): roughly 2.45 vanilla vs 2.67 myopic, i.e. gap roughly 0.2 nats (~, read off plot); small models (14M-70M) gap roughly 0.05-0.15 (~, read off plot).
- Benchmarks: gap widens with size on all four; e.g. LAMBADA at 2.8B roughly 0.58 vanilla vs 0.40 myopic; ARC-Easy roughly 0.65 vs 0.56; PIQA roughly 0.745 vs 0.695; SciQ roughly 0.90 vs 0.83 (~, read off plot). At the smallest sizes the two are nearly equal on PIQA, SciQ, ARC-Easy.
- Stated conclusion: "the importance of pre-caching increases with scale, becoming non-negligible with larger models, e.g. Pythia 2.8B... these larger models are 'planning for the future' in a way that small models cannot."

### Gradient angles (Pythia-410M, Fig 11)
Norm of the myopic gradient is consistently larger than the future gradient: "training is dominated by the effect of each forward pass's parameters on the immediate next-token prediction". Cosine similarity between the two components fluctuates roughly between -0.5 and +0.2 during training (~, read off plot).

## 7. Limitations (stated or evident from the text)
- Natural-language experiments use short sequences (64 tokens) and small models (largest 2.8B). No modern instruction-tuned chat models; no long-form generation.
- GPT-2 results are from-scratch training on 4.6M MS MARCO sequences (not the released GPT-2); Pythia results are *fine-tuning* from vanilla-pre-trained checkpoints for one epoch of 10M sequences, so the myopic Pythia models start from weights that already pre-cache. The authors note the dataset is too small for from-scratch pre-training of the larger models.
- The myopia gap is a property of architecture + data; a small gap "does not say much about any specific model", hence the local bonus, which was measured only for GPT-2.
- The convergence theorem needs strong convexity, smoothness and forward bias, which are assumptions rather than verified properties of real transformers.
- The method measures a *training-time* counterfactual. It gives no inference-time tool to remove pre-caching from an already-trained model and no identification of which features are pre-cached in natural language (the probing is only done in the synthetic task).
- Applications to safety/interpretability are stated as hypotheses for future work.

## 9. Reusable for our experiment

**Concepts that sharpen our hypothesis**
- Our "planning and prose are entangled; the model keeps getting ready for the future in its hidden state" hypothesis maps onto this paper's two mechanisms, which make different predictions about leakage:
  - *Breadcrumbs*: the secret concept is active at story positions simply because features useful for writing the current token (given a prompt that contains the secret) are the same ones that carry the secret forward. Leakage is then a by-product of ordinary next-token computation.
  - *Pre-caching*: the model actively computes secret-related features at positions where they do not help the current token, to prepare the later reveal.
- The paper's evidence: at GPT-2 scale natural language is mostly breadcrumbs (gap 0.12, local bonus 0.02), with pre-caching growing with scale up to 2.8B. It does not tell us which regime 7B+ chat models are in; extrapolating the trend suggests non-negligible pre-caching but that is an inference, not a result in the paper.

**Probing setup**
- Linear probes per layer and per lag, plus per-neuron correlation maps, with a target chosen so the probe cannot compute it from the input alone. For us this is a warning: the secret is in the prompt, so a probe at story positions can succeed just by reading attended prompt content. We need controls (e.g. secret present in prompt but task does not involve a later reveal; or secret mentioned in an unrelated system note) to separate "copied from context" from "being prepared for use".
- The layer-1 "pre-cached but not yet used, sitting in the residual stream until cleaned up by the unembedding" picture is a concrete template for what we would look for: a secret direction present in mid-layer residual stream at positions where the output logits do not need it. Leakage/over-foreshadowing would then be the case where that direction is not fully cleaned up before the unembedding.

**Intervention ideas adapted from the myopic attention mechanism**
- Their stop-gradient is training-time and not directly usable on a frozen 7B model within our budget. But the *local myopic* and *bigram* constructions suggest inference-time analogues: swap or zero the past key/value states for selected positions/heads (e.g. knock out attention from story positions to the secret tokens, or patch in key/values from a run without the secret). That is our planned ablation expressed in their framework.
- Filler-token result: vanilla models use otherwise idle positions for future-oriented computation. This suggests testing whether leakage changes when the model is given "scratch" positions (padding, or a written outline) before the prose.
- Code at the URL above implements myopic attention for GPT-2/Pythia; reusable if we want a small-model sanity check (e.g. a myopically fine-tuned Pythia leaks less/more on a toy secret task). A 2.8B fine-tune on 10M x 64 tokens is feasible on one 48GB GPU in principle, but the paper does not report compute cost.

**Evaluation protocol ideas**
- Per-position analysis (Fig 4): plot the quantity of interest against token position. For us: leak probability / probe decodability by story position, with and without an outline.
- Report a gap relative to a no-context lower bound (their bigram baseline) to put effect sizes in context.

**Implication for "can an external plan offload internal planning?"**
- Supportive in principle: in the local-myopic experiment, when "past hidden states are supplied by a separate model", each forward pass "can focus purely on next-token prediction" and does slightly *better* (3.26 vs 3.28). That is a direct, if small, demonstration that externally supplied future-relevant state relieves the current pass of future preparation. An explicit outline in context is a text-level analogue (my analogy, not the paper's claim).
- Cautionary: at small scale most forward-carrying of information is breadcrumbs, i.e. not a separable planning computation. If secret leakage is breadcrumb-like (the secret is simply salient context that shapes every token), an outline would not remove it, and only removing or suppressing the secret representation itself would. Comparing our (a) outline condition with our (b) ablation condition is therefore a test of which mechanism dominates.
- The paper offers no evidence about instruction-following, withheld information, or long-form generation.
